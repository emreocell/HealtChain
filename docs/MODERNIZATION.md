# Modernization Notes

The original thesis repository was a useful proof of concept, but its public packaging mixed generated dependencies, Hardhat starter files, frontend code, backend code, secrets, and an unsafe public-chain data model. HealthChain v2 turns that prototype into an auditable research and engineering project.

## Major changes

- Removed tracked `node_modules`, Hardhat generated `artifacts/` / `cache/`, local environment files, and starter boilerplate from the source tree.
- Removed committed AI credentials from runtime code and moved secrets to environment-based configuration.
- Replaced plaintext on-chain patient names and conditions with salted off-chain integrity proofs.
- Removed unrestricted admin update/delete paths; the contract is append-only with patient-controlled revocation markers.
- Added patient-to-provider write authorization with tests around authorization boundaries.
- Replaced unsafe dynamic HTML rendering of user/chain values with DOM text rendering.
- Replaced a hardcoded contract address with deployment metadata generated by the deployment script.
- Reworked the AI endpoint into explicitly consented, validated, non-diagnostic educational decision support.
- Migrated smart-contract tooling to Hardhat 3, TypeScript, viem, and Node's built-in test runner.
- Added deterministic dependency locking, CI, dependency audit gates, Dependabot, security documentation, threat modeling, contributor rules, and citation metadata.

## Why hashes instead of medical records?

A public blockchain is a poor place for confidential medical content. Immutability is valuable for integrity proofs, but directly publishing health data creates a privacy problem that cannot be undone. This redesign uses the blockchain as an integrity and audit primitive rather than a database for patient content.

A random 32-byte salt is generated in the browser before hashing the canonical local payload. This makes low-entropy medical terms substantially harder to test through simple dictionary attacks. The original payload and salt remain off-chain in an optional local proof bundle.

## Scope of the modernization

Version 2 modernizes the implementation and security model. It does **not** claim that the original thesis experiments, evaluation, datasets, or academic conclusions were reproduced under the new architecture. Any future research claims should be backed by a separate reproducible evaluation.

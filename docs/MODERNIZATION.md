# Modernization Notes

The original thesis repository was a useful proof of concept, but its public packaging mixed generated dependencies, Hardhat starter files, frontend code, backend code, and secrets. The v2 layout turns that prototype into an auditable research project.

## Major changes

- Removed tracked `node_modules`, Hardhat `artifacts/`, and `cache/` output from the source tree.
- Removed committed `.env` material and hardcoded AI credentials from runtime code.
- Replaced plaintext on-chain patient names and conditions with salted off-chain integrity proofs.
- Removed unrestricted `adminSil` / `adminGuncelle` style mutation paths; the contract is now append-only with patient-controlled revocation markers.
- Added patient-to-provider write authorization and tests around authorization boundaries.
- Replaced dynamic `innerHTML` rendering with safe DOM text rendering.
- Replaced a hardcoded contract address with a deployment config generated by the deploy script.
- Reworked the AI endpoint into an explicitly consented, validated, non-diagnostic educational decision-support endpoint.
- Added CI, dependency update automation, security documentation, threat modeling, contributor rules, and reproducible project scripts.

## Why hashes instead of medical records?

A public blockchain is a poor place for confidential medical content. Immutability is valuable for integrity proofs, but directly publishing health data creates a privacy problem that cannot be undone. This redesign uses blockchain as an integrity/audit primitive rather than a database for patient content.
